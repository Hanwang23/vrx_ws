# han_usv_controller 功能与运行指南

> 这是 `han_usv_controller` 当前全量参考手册，包含主场景和各专项压力场。如果只需要本条对话修改的范围、唯一推荐启动命令和验收方法，请看 `han_usv_controller/本条对话修改专用启动教程.md`。

## 1. 最重要的运行规则

同一时刻只能运行一套 VRX 仿真。不要同时执行下列任意两条命令：

```bash
ros2 launch han_usv_controller simulation.launch.py
ros2 launch han_usv_controller colregs_learning.launch.py
bash han_usv_controller/scripts/run_colregs_learning.sh
bash han_usv_controller/scripts/run_three_evaluations.sh
```

同时运行会生成多个 WAM-V 和多个推进器发布者，导致 `control_conflict`、初始碰撞或任务状态跳变。

开始前，先在所有仿真终端按 `Ctrl+C`，然后检查：

```bash
pgrep -af 'ros2 launch han_usv_controller|gz sim|autonomous_usv|moving_target'
```

无输出才表示已经干净。自动评测器会再次清理本项目的旧 Gazebo、controller、EKF、bridge、monitor 和 moving-target 进程。

## 3. 推荐主场景

```bash
cd /home/han/Ai_ws/Study/vrx_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch han_usv_controller colregs_learning.launch.py
```

这一条命令会启动：

1. 官方 Wayfinding 任务与 WAM-V。
2. `robot_localization` EKF 与独立 PlanarEKF 回退。
3. `100 m x 100 m`、`0.5 m` 分辨率的滚动占据栅格。
4. Dubins State Lattice A* 分段规划。
5. 现有 ILOS 路径跟踪和 PID 推进器控制。
6. 6 对红绿航道浮标，共 12 枚。
7. 2 艘动态目标船与 COLREGs CPA/TCPA 监督。
8. Gazebo 和中文自定义名称的 RViz。

启动后先等待约 15 秒。WAM-V 只在官方任务进入 `running` 后开始动作。

## 4. RViz 图层

- `控制器决策与路径`：规划路径、实际轨迹、XTE、目标方向、控制方向和动态船。
- `浮标候选 (激光聚类)`：黄色圆环表示三维激光经水面滤除、聚类和多帧确认得到的静态小目标。
- `二维激光雷达回波 (130 m)`：亮绿色原始扫描点。
- `滚动占据栅格`：默认关闭半透明显示，需要时手动勾选。
- `WAM-V 三维激光雷达`：默认关闭，用于检查原始点云。

画面颜色：

- 青色粗线：当前规划路径。
- 黄色曲线：实际历史轨迹。
- 品红色：当前横向误差 XTE。
- 蓝色箭头：当前官方航点方向。
- 白色箭头：ILOS 名义航向。
- 绿色/黄色/红色控制箭头：巡航/避障/制动控制指令。
- 橙色方框：动态船；变红表示当前 COLREGs 风险目标。
- 黄色圆环：激光浮标候选。

注意：激光只能生成浮标形状候选，不能判断红/绿颜色。红绿语义识别需要后续摄像头检测器。RViz/Ogre 的 Marker 默认字体不包含中文字形，因此画面内 Marker 标签保留英文，左侧自定义图层名称使用中文。

## 5. 用终端确认它真的在工作

另开一个终端：

```bash
cd /home/han/Ai_ws/Study/vrx_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
```

查看控制器状态：

```bash
ros2 topic echo /autonomous_usv/status --field data
```

重点字段：

```text
state
num_collisions
estimator_source
robot_localization_healthy
map_known_cells
guidance_mode
cross_track_error_m
dynamic_track_count
buoy_candidate_count
colregs_active
colregs_encounter
colregs_tcpa_s
colregs_dcpa_m
```

检查两艘动态船发布器：

```bash
ros2 topic info /autonomous_usv/dynamic_targets
```

默认 COLREGs 场景期望 `Publisher count: 2`。

检查浮标候选图层：

```bash
ros2 topic info /autonomous_usv/buoy_candidates
ros2 topic echo /autonomous_usv/buoy_candidates --once
```

候选只在浮标进入约 22 m 感知区且连续确认后出现，短时为 0 不代表雷达失效。

## 6. 自动验收

运行一次完整的 COLREGs 官方任务：

```bash
cd /home/han/Ai_ws/Study/vrx_ws
bash han_usv_controller/scripts/run_colregs_learning.sh
```

脚本会自动构建、清理旧进程、启动无界面仿真、采集指标并判断：

- 官方三个航点完成。
- 0 碰撞。
- 官方平均和单航点误差达标。
- `robot_localization` 持续健康。
- 滚动占据栅格获得足够观测。
- State Lattice 进入制导链且无持续 fallback。
- 最多动态跟踪数至少为 2。
- COLREGs 真实激活样本至少为 20。

通过时最后显示：

```text
TRIAL 1/1: PASS all thresholds satisfied
```

查看最新结果：

```bash
python3 -m json.tool han_usv_controller/evaluation/latest.json | less
```

自动评测运行期间，不要再打开任何 Gazebo/ROS 2 launch 命令。

## 8. han_usv_controller 已添加的功能

1. 可重复自动评测：完成率、碰撞、净空、官方误差、XTE、角速度、规划耗时、原地旋转和多目标指标。
2. `robot_localization` EKF，并保留独立 PlanarEKF 健康检查与回退。
3. 激光滚动占据栅格、障碍膨胀、衰减和 RViz 显示。
4. Dubins State Lattice A*，包含最小转弯半径、子目标滚动规划、障碍触发重规划和 fallback 监控。
5. 复用 ILOS + PID 的路径跟踪，加入曲率限速、航向前馈和安全制动。
6. RViz 规划路径与实际轨迹对比、XTE、20 秒平均/最大误差和控制状态。
7. 高对比度 130 m 二维激光岸线显示。
8. 12 枚学习浮标、2 艘可见动态船、多目标跟踪和 CPA/TCPA/COLREGs 监督。
9. 浮标候选雷达图层，使用真实点云聚类结果并排除专用动态船。
10. RViz 自定义图层中文名称，Marker 字体不支持中文的部分保留英文。
11. 自动评测前的旧进程清理，包括 Gazebo、controller、bridge、EKF、monitor、GNSS 适配器和动态目标。

## 9. 当前边界

- 动态船位置使用仿真专用检测 Topic，尚不是可部署的雷达/视觉船舶检测器。
- 激光浮标候选不能判断红/绿颜色。
- COLREGs 是教学仿真监督层，不是认证的完整船舶避碰系统。
- Gazebo 退出时可能在 VRX `libWaveVisual` 析构阶段打印堆栈；只要它发生在 `Ctrl+C` 之后，不影响运行结果。
