# 本条对话修改专用启动教程

## 1. 范围声明

本文只覆盖当前这条对话中实现和继续修正的 `han_usv_controller` 功能：

1. 自动化评测与 30 次可复现随机浮标评测。
2. `robot_localization` EKF 与独立 PlanarEKF 回退。
3. 滚动占据栅格、障碍衰减和安全膨胀。
4. Dubins State Lattice A* 与在线重规划。
5. 复用现有 ILOS + PID 跟踪闭环。
6. 规划路径、实际轨迹、XTE 和 20 秒跟踪统计。
7. 高对比度 130 m 二维激光回波和岸线总览。
8. 12 枚学习浮标和 2 艘可见动态船。
9. 多动态目标跟踪、CPA/TCPA 和教学型 COLREGs 监督。
10. RViz 中文自定义图层名称。
11. 基于真实三维激光聚类的浮标候选圆环。
12. 自动评测前的旧进程隔离和两艘动态船硬验收门槛。
13. 仿真独占锁，阻止重复 Gazebo/WAM-V 启动。
14. 浮标 Marker 定点删除，消除 RViz 周期性闪烁。

本文不包含工作区根目录中旧版：

```text
/home/han/Ai_ws/Study/vrx_ws/autonomous_controller.py
/home/han/Ai_ws/Study/vrx_ws/launch_wayfinding.sh
```

这两个文件属于先前的简化 Wayfinding 方案，不是本条对话的推荐入口。

## 2. 一条命令为什么能启动全部功能

启动链如下：

```text
colregs_learning.launch.py
  -> simulation.launch.py
     -> VRX Wayfinding 官方任务
     -> gnss_odometry_adapter
     -> robot_localization ekf_node
     -> autonomous_usv
        -> PlanarEKF 健康检查/回退
        -> 滚动占据栅格
        -> Dubins State Lattice A*
        -> ILOS + PID
        -> 路径/轨迹/XTE RViz Marker
        -> COLREGs 与浮标候选 Marker
     -> pointcloud.rviz
  -> 12 枚红绿浮标
  -> 2 艘动态目标船
```

因此，本条对话所有可视化修改的唯一推荐入口是：

```bash
ros2 launch han_usv_controller colregs_learning.launch.py
```

`simulation.launch.py` 只是被它内部包含的基础层，不是本文推荐你单独运行的最终演示入口。

## 3. 运行前清理

同一时刻只能运行一套 VRX 仿真。在所有仿真终端按 `Ctrl+C`，然后执行：

```bash
pgrep -af 'ros2 launch han_usv_controller|gz sim|autonomous_usv|moving_target'
```

必须无输出。如果仍有输出，回到对应终端按 `Ctrl+C`。

不要在主场景运行时再执行：

```bash
ros2 launch han_usv_controller simulation.launch.py
bash han_usv_controller/scripts/run_colregs_learning.sh
```

旧版本在这种情况下会出现重复 WAM-V、`control_conflict` 和虚假碰撞。当前版本先检查已经运行的 Gazebo server，再获取工作区独占锁，会在第二套仿真生成 WAM-V 前拒绝启动。根据冲突来源会报告以下一种消息：

```text
A han_usv_controller simulation is already running (owner PID ...)
An existing Gazebo Sim server was detected before launch (PID ...)
```

看到此消息时，保留第一套主场景，在第二个终端按 `Ctrl+C` 即可。锁会随第一套 launch 退出自动释放，不需要手工删除 `/tmp` 下的锁文件。

## 4. 首次构建

```bash
cd /home/han/Ai_ws/Study/vrx_ws
source /opt/ros/humble/setup.bash
export GZ_VERSION=garden

colcon build --merge-install --base-paths han_usv_controller \
  --packages-select han_usv_controller

source install/setup.bash
```

`Finished <<< han_usv_controller` 表示构建成功。

## 5. 启动本条对话的全部界面功能

```bash
cd /home/han/Ai_ws/Study/vrx_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch han_usv_controller colregs_learning.launch.py
```

期望看到：

1. Gazebo 中有且只有 1 艘 WAM-V。
2. 约 5 秒后出现 2 艘橙白色动态船。
3. 约 6.5 秒后开始生成 6 对红绿浮标。
4. RViz 左侧显示 `控制器决策与路径`、`浮标候选 (激光聚类)`、`二维激光雷达回波 (130 m)` 和 `滚动占据栅格`。
5. 青色线是规划路径，黄色线是实际轨迹，品红线是 XTE。
6. 黄色圆环是激光浮标候选，也是唯一的静态小目标聚类标记；旧的重复红色障碍点已删除，候选更新时不会再全层闪烁。
7. 橙色方框是动态船；被 COLREGs 选中后变红。

WAM-V 会等官方任务进入 `running` 后才动作，启动后先等待约 15 秒。

## 6. 确认所有层都在工作

另开终端：

```bash
cd /home/han/Ai_ws/Study/vrx_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 topic echo /autonomous_usv/status --field data
```

检查以下字段：

```text
robot_localization_healthy
estimator_source
map_known_cells
guidance_mode
lattice_fallback
cross_track_error_m
dynamic_track_count
buoy_candidate_count
colregs_active
colregs_tcpa_s
colregs_dcpa_m
num_collisions
```

正常关系：

- `estimator_source` 稳定后应为 `robot_localization`。
- `map_known_cells` 应持续大于 0。
- `guidance_mode` 航行时主要为 `lattice_ilos`。
- `lattice_fallback` 应为 `false`。
- `dynamic_track_count` 稳定后应为 2。
- `buoy_candidate_count` 会随距离和遮挡变化，可以暂时为 0。
- `colregs_active` 只在预测存在会遇风险时为 `true`。
- `num_collisions` 必须保持 0。

确认两艘动态船发布器：

```bash
ros2 topic info /autonomous_usv/dynamic_targets
```

应显示：

```text
Publisher count: 2
```

## 7. 本条对话功能的自动验收

先停止第 5 节的手动场景，确认没有 Gazebo 后，单独执行：

```bash
cd /home/han/Ai_ws/Study/vrx_ws
bash han_usv_controller/scripts/run_colregs_learning.sh
```

这条命令使用同一个 `colregs_learning.launch.py`，但关闭 Gazebo GUI 和 RViz，并硬性检查：

- 官方三个航点完成。
- 0 碰撞。
- EKF 健康。
- 滚动栅格有效。
- State Lattice 确实进入制导链。
- fallback 为 0。
- 跟踪到 2 艘动态船。
- COLREGs 激活样本不少于 20。
- 官方航点误差达标。

通过时显示：

```text
TRIAL 1/1: PASS all thresholds satisfied
```

自动评测运行期间不要再启动 `simulation.launch.py` 或其他 Gazebo。
