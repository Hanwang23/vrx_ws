# han_usv_controller 代码扫描功能与指令总结

> 本文仅依据当前 Python/C++ 源码、ROS 2 launch、YAML 配置、包入口和 Shell 脚本整理，没有使用项目内 README 或其他 Markdown 文档作为功能判断依据。

## 1. 系统定位

当前主要实现是 ROS 2 包 `han_usv_controller`，用于在 VRX/Gazebo 中控制 WAM-V 无人艇。主闭环为：

```text
VRX/Gazebo
  -> GPS + IMU + LaserScan + PointCloud2
  -> GNSS里程计 / robot_localization / 内部平面EKF
  -> 滚动占据栅格与动态目标跟踪
  -> Direct LOS / Dubins / State Lattice路径规划
  -> ILOS路径跟踪
  -> 雷达局部避障与COLREGs监督
  -> 速度、航向和角速度控制
  -> 左右推进器
```

代码注册了以下 ROS 2 可执行入口：

```text
autonomous_usv
gnss_odometry_adapter
fit_3dof_model
moving_target
regression_monitor
run_evaluation
```

## 3. 启动时必须知道的行为

VRX 任务启动状态依次为：

```text
initial -> ready -> running
```

在 `initial` 和 `ready` 阶段，控制器会保持推力为零。当前机器实测通常需要约 20～35 秒才进入 `running`。出现下面的日志后，船才会开始自主运动：

```text
Task wayfinding: ready -> running
```

实时检查：

```bash
ros2 topic echo /autonomous_usv/status
```

检查左推进器：

```bash
ros2 topic echo /wamv/thrusters/left/thrust
```

运行阶段应看到 `state` 变为 `navigating`、`avoiding`、`aligning` 等，并出现非零推力。

同一时间只能运行一套完整仿真。当前代码会检测已有 launch 锁和以下两类 Gazebo 进程：

```text
gz sim ...
ruby /usr/bin/gz sim ...
```

如果已有仿真，新 launch 会直接拒绝启动，防止生成第二艘 WAM-V。

## 4. 基础自主航行

```bash
ros2 launch han_usv_controller simulation.launch.py
```

该命令启动：

- VRX/Gazebo 世界和一艘 WAM-V；
- 主控制节点 `autonomous_usv`；
- GNSS 到里程计适配节点；
- `robot_localization` EKF；
- 默认 RViz。

当前代码支持接收官方 Wayfinding 航点，按顺序驶向目标，在捕获位置后对准最终艏向。

低资源运行：

```bash
ros2 launch han_usv_controller simulation.launch.py \
  headless:=True rviz:=False
```

使用官方计时世界：

```bash
ros2 launch han_usv_controller simulation.launch.py \
  timed_competition:=True
```

竞赛话题模式：

```bash
ros2 launch han_usv_controller simulation.launch.py \
  competition_mode:=True
```

不启动外部 `robot_localization`，仅使用内部 EKF：

```bash
ros2 launch han_usv_controller simulation.launch.py \
  robot_localization:=False
```

严格保留官方发布的航点顺序：

```bash
ros2 launch han_usv_controller simulation.launch.py \
  preserve_waypoint_order:=True
```

默认情况下，代码会按照当前位置执行最近邻航点排序。

## 5. Station Keeping

控制节点订阅：

```text
/vrx/stationkeeping/goal
```

收到目标后会驶向目标经纬度、对准指定艏向，并在漂出容差后重新追踪。

```bash
ros2 launch han_usv_controller simulation.launch.py \
  world:=stationkeeping_task
```

是否能启动该世界取决于本机 VRX 安装是否提供对应世界资源。

## 6. 固定浮标避障场景

```bash
ros2 launch han_usv_controller buoy_course.launch.py
```

代码会在基础 Wayfinding 中生成：

- 12 个红绿门浮标；
- 4 个橙色障碍浮标；
- 1 艘受控 WAM-V。

总计 16 个附加浮标，不会生成额外目标船。该场景已实测进入 `running` 并输出非零推力。

如果模型生成太早，可延后：

```bash
ros2 launch han_usv_controller buoy_course.launch.py \
  spawn_delay:=10.0
```

## 7. 随机浮标避障场景

```bash
ros2 launch han_usv_controller random_buoy_course.launch.py \
  scenario_seed:=1000
```

随机生成器会创建 12 个门浮标和 4 个橙色障碍，并检查：

- 浮标之间的最小距离；
- 官方航点捕获区净空；
- WAM-V 出生点净空；
- 是否位于预设安全水域。

相同 `scenario_seed` 会生成相同布局。该场景已实测进入 `running` 并输出非零推力。

## 8. State Lattice 压力场

```bash
ros2 launch han_usv_controller lattice_stress.launch.py
```

该 launch 包含固定浮标场，并额外生成 3 个橙色障碍组成障碍带。用途是使解析 Dubins 路径受阻，从而触发栅格搜索。

该场景实测结果包括：

```text
navigating
avoiding
Guidance path replanned: reason=lattice_obstacle
```

关注状态字段：

```text
guidance_mode
lattice_expanded_states
lattice_planning_time_ms
lattice_fallback
```

## 9. 八航点课程

```bash
ros2 launch han_usv_controller multi_waypoint_course.launch.py
```

代码会在运行时读取模板 SDF，生成临时的 8 航点世界，并强制保留航点发布顺序。退出时会删除临时世界目录。

该场景已实测加载 8 个航点、进入 `running` 并产生非零推力。

## 10. 动态目标与 COLREGs 场景

```bash
ros2 launch han_usv_controller colregs_learning.launch.py
```

该场景设计上会出现多艘船：

```text
1 艘受控 WAM-V
2 艘动态目标船
```

这不是重复生成 WAM-V。两艘目标船用于动态目标跟踪和 COLREGs 测试。代码同时生成 12 个红绿航道浮标。

关闭第二艘目标船：

```bash
ros2 launch han_usv_controller colregs_learning.launch.py \
  spawn_second_target:=False
```

此时仍会保留第一艘目标船。如果只想看到一艘船，应运行基础 `simulation.launch.py`。

动态目标数据发布到：

```text
/autonomous_usv/dynamic_targets
```

目标坐标系为：

```text
han_usv_odom
```

代码实现：

- 多目标数据关联；
- 目标位置与速度平滑；
- 运动目标确认；
- CPA、TCPA 计算；
- 对遇、横越、追越等会遇评估；
- 最紧急目标选择；
- 右转航向偏置与速度缩放。

默认配置不允许普通点云聚类直接触发 COLREGs：

```text
colregs.use_pointcloud_tracks = false
```

## 11. 仅启动控制链

如果 Gazebo 或真实传感器已经由其他方式启动：

```bash
ros2 launch han_usv_controller controller.launch.py
```

该命令启动 GNSS 适配、`robot_localization` 和主控制器，不启动 Gazebo。

## 12. 自定义 GNSS 航点

主节点支持 `task_mode=custom`，航点格式为：

```text
纬度,经度
纬度,经度,艏向角度
```

示例：

```bash
ros2 run han_usv_controller autonomous_usv \
  --ros-args \
  -p task_mode:=custom \
  -p start_without_task:=True \
  -p "custom_waypoints:=['-33.7200,150.6700,90','-33.7210,150.6710,180']"
```

这条命令只启动控制器，不启动仿真。必须已有对应传感器和推进器话题。`start_without_task:=True` 用于跳过 VRX 任务状态门控。

## 13. 状态估计

代码包含两套估计来源：

1. 内部六状态平面 EKF；
2. `robot_localization` 的 `/odometry/filtered`。

内部状态包括东、北位置，东、北速度，航向和艏摇角速度。代码会检查外部 EKF 数据新鲜度、协方差和与内部 EKF 的位置差异；外部结果不健康时回退内部 EKF。

## 14. 路径规划与控制能力

实际控制链包含：

- Direct LOS 目标方向控制；
- 直线 ILOS 路径跟踪；
- 曲率受限 Dubins 路径；
- State Lattice / Hybrid A* 风格栅格搜索；
- 曲率预瞄限速和角速度前馈；
- 航速 PID；
- 航向与角速度级联控制；
- 最终艏向对准和对准角速度限制。

可能出现的制导模式：

```text
direct_los
ilos_line
dubins_ilos
lattice_ilos
```

## 15. 感知、地图和避障

主节点订阅：

```text
/wamv/sensors/gps/gps/fix
/wamv/sensors/imu/imu/data
/wamv/sensors/lidars/lidar_wamv_sensor/scan
/wamv/sensors/lidars/lidar_wamv_sensor/points
/vrx/wayfinding/waypoints
/vrx/stationkeeping/goal
/vrx/task/info
/autonomous_usv/dynamic_targets
/odometry/filtered
```

点云处理包含降采样、水面平面拟合、高度过滤、二维聚类和多帧轨迹关联。

滚动占据栅格默认参数：

```text
100 m × 100 m
0.5 m 分辨率
40 m 最大融合距离
3 m 障碍膨胀
```

局部安全逻辑包括：

- 警告区减速；
- 自由间隙方向选择；
- 近障碍紧急反推；
- 无进展检测；
- 定时倒车脱困；
- 最终艏向对准前的障碍检查；
- 避障结束后的路径重规划。

## 16. 安全门控

以下状态会使推进器保持为零：

```text
waiting_for_gps
waiting_for_imu
waiting_for_lidar
gps_timeout
imu_timeout
lidar_timeout
ekf_unhealthy
control_conflict
task_initial / task_ready / task_unknown
```

控制器会检查推进器话题发布者数量。不要同时运行自主控制器、键盘遥控、自动直行或其他推进器发布节点。

检查发布者：

```bash
ros2 topic info /wamv/thrusters/left/thrust --verbose
ros2 topic info /wamv/thrusters/right/thrust --verbose
```

基础场景三轮：

```bash

```

八航点评测：

```bash
bash han_usv_controller/scripts/run_multi_waypoint_evaluations.sh
```

```bash

```

State Lattice 压力评测：

```bash

```

```bash

```

```bash

```

```bash

  --launch-file simulation.launch.py
```

## 19. 模型辨识

控制器包含可选状态和控制量 CSV 记录器，默认关闭。启用后可用以下入口拟合三自由度一阶模型：

```bash
ros2 run han_usv_controller fit_3dof_model \
  han_usv_controller/model_data/usv_identification.csv \
  --output han_usv_controller/model_data/fitted_model.json
```

代码可以拟合纵向速度模型、艏摇模型和横荡阻尼，并输出模型准备状态。

当前 NMPC 仅有模型接口和安全门控，没有能够接管推进器的求解器。即使请求 `nmpc`，实际后端仍会保持为 `ilos_pid`。

```bash

```

```bash
python3 direct_controller.py
```

旧版独立自主控制器：

```bash
python3 autonomous_controller.py
```

相机查看器：

```bash
python3 camera.py
```

## 21. 推荐运行顺序

```bash
# 1. 基础场景
ros2 launch han_usv_controller simulation.launch.py

# 2. 固定浮标
ros2 launch han_usv_controller buoy_course.launch.py

# 3. 随机浮标
ros2 launch han_usv_controller random_buoy_course.launch.py scenario_seed:=1000

# 4. State Lattice压力场
ros2 launch han_usv_controller lattice_stress.launch.py

# 5. 八航点
ros2 launch han_usv_controller multi_waypoint_course.launch.py

# 6. 动态目标与COLREGs
ros2 launch han_usv_controller colregs_learning.launch.py
```

每次只运行其中一条完整场景命令。退出上一场景后，确认没有残留进程再启动下一场景：

```bash
pgrep -af 'gz sim|ros2 launch|autonomous_usv|moving_target'
```

## 22. 当前实测结论

以下完整场景均已实际启动到 `running`，并观察到非零推进器输出：

```text
simulation.launch.py
buoy_course.launch.py
random_buoy_course.launch.py
lattice_stress.launch.py
multi_waypoint_course.launch.py
colregs_learning.launch.py
```

其中 `colregs_learning.launch.py` 会主动生成目标船；其他场景正常情况下只有一艘 WAM-V。Gazebo 的 WaveVisual 插件在按 `Ctrl+C` 退出时可能打印段错误堆栈，这是退出阶段问题；再次启动时，新的重复仿真检测会阻止残留服务器造成第二艘 WAM-V 或传感器连接错误。
