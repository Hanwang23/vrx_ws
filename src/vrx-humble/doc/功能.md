## 1. vrx_gz

**路径**: `src/vrx-humble/vrx_gz/`
**版本**: 0.0.0 | **许可证**: Apache 2.0
**维护者**: Carlos Aguero (Open Robotics)

### 1.1 概述

VRX 仿真竞赛的**核心 Gazebo 集成包**，为 Gazebo Sim (gz-sim7) 提供完整的仿真环境，包括：
- 各竞赛任务的世界文件（SDF 格式）

- 机器人模型生成与 Launch 配置

## 2. vrx_ros

**路径**: `src/vrx-humble/vrx_ros/`
**版本**: 0.0.0 | **许可证**: Apache 2.0
**维护者**: Carlos Aguero (OSRF)

### 2.1 概述

VRX 仿真竞赛的 **ROS 2 桥接辅助包**，体积小巧但功能关键。解决 Gazebo 仿真环境与 ROS 2 之间的**坐标系和数据格式转换**问题，包含两个 C++ 节点和一个 Python 监控脚本。

### 2.2 C++ 节点

#### optical_frame_publisher

- **功能**: 将传感器数据从机器人坐标系（robot frame）转换为 ROS 标准光学坐标系（optical frame）
- **坐标系变换**: RPY = -90, 0, -90 度
- **订阅**: `input/image`（Image）+ 可选 `input/camera_info`（CameraInfo）
- **发布**: `output/image`（frame_id 添加 `_optical` 后缀）+ `output/camera_info`
- **优化**: 按需订阅模式，无订阅者时自动取消输入订阅

#### pose_tf_broadcaster

- **功能**: 将 Gazebo 位姿数据转发为 ROS TF 变换树
- **订阅**: `pose`（动态 TF）+ `pose_static`（静态 TF）
- **发布**: `TransformBroadcaster` + `StaticTransformBroadcaster`
- **参数**: `world_frame`（过滤掉世界坐标系的 TF，避免冲突）

### 2.3 Python 脚本

#### monitor_sim.py

- **功能**: 监控 Gazebo 仿真进程生命周期
- **工作流程**: 启动后等 10 秒 → 每秒 `pgrep 'gz sim -v 4'` → Gazebo 退出后自动退出
- **用途**: 作为子进程被 Launch 文件调用，实现仿真结束后自动关闭 ROS 节点

### 2.4 依赖关系

**构建**: `ament_cmake`
**运行**: `geometry_msgs`, `rclcpp`, `sensor_msgs`, `tf2`, `tf2_ros`, `ros_gz_bridge`, `ros_gz_interfaces`
**CMake 额外**: `gz-msgs9`, `gz-transport12`, `tf2_msgs`

## 3. vrx_gazebo

**路径**: `src/vrx-humble/vrx_urdf/vrx_gazebo/`
**版本**: 1.3.0 | **许可证**: Apache 2.0
**维护者**: Carlos Aguero, Jose Luis Rivero (OSRF)

### 3.1 概述

VRX 竞赛的**模型资产与合规性检查包**。提供 WAM-V 平台所需的各类传感器和组件的 Gazebo SDF 模型，以及通过 YAML 配置文件自动生成 URDF 的工具链。

### 3.2 模型清单（7 个）

| 模型 | 类型 | 质量 | 说明 |
|------|------|------|------|
| `3d_lidar` | 传感器 | 1 kg | 3D 激光雷达，圆柱碰撞体 |
| `ball_shooter` | 执行器 | 2×0.5 kg | 弹射器（基座 + 发射管），旋转关节 |
| `battery` | 能源 | 23.5 kg | 海洋电池，参考 Torqeedo Power 24-3500 |

| `mono_camera` | 传感器 | 0.3 kg | 单目相机 |
| `sensor_post` | 结构 | 0.6 kg | 传感器支架（立柱 + 悬臂） |

所有模型均使用 **PBR 材质管线**（Albedo / Metalness / Normal / Roughness 贴图）。

### 3.3 URDF 生成机制

```
YAML 配置文件 → generate_wamv.launch.py → generate_wamv.py
  → configure_wamv.py（合规性检查 + xacro 生成）
  → xacro 命令 → 最终 URDF
```

### 3.4 合规性检查体系

**组件合规性**:
- 位置边界框：前部区域（1×1×1m）+ 后部区域（0.5×1×1m）
- 数量限制：相机 ≤3、GPS ≤1、IMU ≤1、激光雷达 ≤2、弹射器 ≤1、声学定位器 ≤1

**推进器合规性**:
- 5 个位置边界框（左后/右后/左前/右前/中央），每区域最多 1 个推进器
- 引擎类型最多 4 个

### 3.5 Launch 文件

| 文件 | 功能 |
|------|------|
| `generate_wamv.launch.py` | WAM-V URDF 生成（锁定模式、组件/推进器 YAML） |
| `rviz.launch.py` | 启动 RViz2 可视化 |

### 3.6 依赖关系

**运行**: `rclpy`, `std_msgs`, `ament_index_python`, `wamv_description`, `wamv_gazebo`, `xacro`, `numpy`, `PyYAML`

### 5.3 传感器宏模板

#### 相机 (`wamv_camera`)
- 分辨率 1280×720，帧率 30fps，水平视场角 ~80°
- 高斯噪声（stddev=0.007）
- 结构：支撑柱 → 支撑臂 → 相机 → 光学坐标系

#### GPS (`wamv_gps`)
- Gazebo `navsat` 传感器，更新率 20Hz

#### IMU (`wamv_imu`)
- 更新率 100Hz，ENU 参考坐标系
- 角速度噪声：stddev=0.009，动态偏差相关时间 400s
- 线加速度噪声：stddev=0.021，动态偏差相关时间 175s

#### 3D 激光雷达 (`wamv_3d_lidar`)
- Gazebo `gpu_ray` 传感器
- 水平全周扫描（1875 采样点），垂直 16 束（±15°）
- 最大距离 130m，噪声 stddev=0.01

#### 声学定位器 (`wamv_pinger`)
- `libAcousticPingerPlugin.so` 插件
- 距离噪声 stddev=3.0m，方位噪声 stddev=0.01 rad
- 可动态设置声源位置

#### 球发射器 (`wamv_ball_shooter`)
- `libBallShooterPlugin.so` 插件
- 每次 4 发，发射力 65N

#### 地面真值 (`wamv_p3d`)
- `gz-sim-odometry-publisher-system` 插件
- 三维里程计，频率 10Hz

### 5.4 推进器布局

#### H 型布局（默认）
- **2 个推进器**：左后 + 右后
- 最简单的差速驱动

#### T 型布局
- **3 个推进器**：左后 + 右后 + 正中横向
- 增加侧移能力

#### X 型布局
- **4 个推进器**：X 型对称布置
- 全方位运动能力
